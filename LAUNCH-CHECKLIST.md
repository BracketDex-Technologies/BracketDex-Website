# Website launch checklist

Updated 1 November 2026.

## Implemented and checked locally

- Custom missing-page screen returns HTTP 404 and links to main pages.
- All eight public pages have distinct titles, descriptions, canonical URLs, Open Graph and Twitter tags.
- Default share image is generated by `src/app/opengraph-image.tsx` at 1200 × 630; no placeholder image is needed.
- Rendered images on the public pages have alt attributes. Decorative logos and illustrations use empty alt where surrounding text already describes them; service and scenario illustrations have descriptive alt.
- Navigation and footer link all public pages. Main navigation destinations respond with HTTP 200.
- `/sitemap.xml` and `/robots.txt` respond with HTTP 200. Sitemap excludes `/thank-you`; robots allows public crawling and points at the production sitemap.
- Contact form validates on the server, checks its honeypot, limits requests, and sends through Web3Forms from the endpoint. The client redirects only after confirmed delivery.
- `/thank-you` is noindex and excluded from the sitemap. Its title no longer repeats the company name.
- GA4 is optional, disabled without a valid ID, and loads only after acceptance for visitors in every region. Decline and Accept are equally available. Cookie settings allows withdrawal.
- Privacy text describes Web3Forms and optional analytics, with the actual business contact details.
- FAQ already contains business questions. No invented reviews, names, photos, ratings, or review schema were added.

## Required before production launch

1. Configure `WEB3FORMS_ACCESS_KEY` in the host environment (legacy `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY` is also supported). Confirm your Web3Forms plan supports server submissions and restrict accepted domains in the provider dashboard if available. Run one real enquiry yourself and confirm inbox delivery and redirect. No real test enquiry was sent during this implementation.
2. Supply `NEXT_PUBLIC_GA_MEASUREMENT_ID` from your GA4 web data stream; rebuild after setting it. Never use `G-XXXXXXXXXX`. Accept analytics and verify your visit in Realtime. Decline on a fresh browser and confirm there are no requests to Google Analytics or Tag Manager.
3. In GA4, create an event named `enquiry_confirmation` from `page_view` where `page_location` contains `/thank-you`, then mark it as a key event. This measures confirmation-page visits, which can also include direct visits; inbox delivery remains the authoritative submission record. Check the event rules in your current GA4 interface.
4. Live checks on 1 November confirm HTTP redirects to HTTPS and both apex and www reach `https://www.bracketdex.com/` with HTTP 200. Canonical URLs now use www to match that deployment. Live robots.txt and sitemap.xml also return HTTP 200. Recheck after deploying these changes.
5. Add the domain to Google Search Console and verify through DNS, or configure `GOOGLE_SITE_VERIFICATION` with the HTML-tag token and redeploy. Submit `https://www.bracketdex.com/sitemap.xml` and request homepage indexing.
6. Review the privacy policy against your hosting, email retention, legal obligations, and Web3Forms processing arrangements. No fixed retention period or compliance certification has been invented.
7. Obtain permission and exact customer wording before publishing testimonials. Content slots: approved quote, customer display name, role/company, permission date, optional approved photo. Until supplied, do not publish fabricated customer content or stars.
8. Confirm the existing FAQ answers and business contact details. Preview the production URL in LinkedIn/WhatsApp to check cached sharing cards.

## Operational limitations

Rate limiting is per running server instance and resets on restart. For a multi-instance/serverless deployment, configure a shared rate-limit store or host/WAF rule before relying on it for sustained abuse protection. Web3Forms also applies its own provider controls. CAPTCHA can be added if actual spam warrants it.

Live delivery, analytics reporting, DNS verification, certificate configuration and production redirects require the relevant configured accounts. They are not marked complete by local checks.

Consent controls were exercised on an isolated local server with a test-only ID: no Google request before acceptance or after decline, tag loads after acceptance, stored choice survives reload, withdrawal removes the loaded runtime. Google requests were intercepted so test data was not transmitted. No real GA4 ID or Search Console verification token is available in the workspace. `.env.example` contains an existing Web3Forms key, but no local environment file configures delivery; confirm ownership and configure it before a real submission test.
